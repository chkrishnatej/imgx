$ imgx

Convert images from the terminal. Five output formats, the inputs you actually have, no ImageMagick.

zsh
$ imgx diagram.svg -w 2400
ok    diagram.svg -> diagram.png  2400x1200  84.2 KB

$ imgx screenshots/ -f webp -q 90 -o build/webp
ok    screenshots/a.png -> build/webp/a.webp  1440x900  62.1 KB
ok    screenshots/v2/b.png -> build/webp/v2/b.webp  1440x900  58.7 KB
2 converted

From source

No install

One-off run

Run straight from a clone, without touching your PATH.

bun run src/cli.ts \

Usage

imgx <input...> [options]

  Inputs are files, directories (walked recursively) or globs.
  Without --out, files are written next to their source as png.

  -o, --out <path>       Output file, or directory (created if missing,
                         with the input folder structure mirrored inside)
  -f, --format <fmt>     png | jpeg | webp | avif | tiff      [default: png]
  -w, --width <px>       Target width. SVGs render at exactly this size,
                         raster images are only ever shrunk
      --height <px>      Target height, ignored when --width is set
  -s, --scale <n>        SVG only: render at n times its intrinsic size
  -q, --quality <1-100>  Quality for jpeg, webp and avif       [default: 85]
      --background <css> Color behind JPEG transparency      [default: white]
                         #rrggbb, #rgb, rgb(r,g,b), or a name:
                         white black grey gray red green blue
      --overwrite        Replace existing files instead of skipping them
      --dry-run          Print what would be written, change nothing
  -h, --help             Show this help
      --version          Show the version

The full flag reference lives in the CLI reference, and the contract lives in the man page.

Examples

# a 1200px-wide PNG for a blog post
imgx hero.svg -w 1200

# the format nothing on macOS writes: webp
imgx screenshot.png -f webp -q 90 -o images/

# a whole folder, mirrored into a build directory that does not exist yet
imgx screenshots/ -f webp -q 90 -o build/webp

# one file out of many, to an exact name
imgx logo.svg -o static/logo-2x.png

# retina export of a diagram
imgx architecture.svg -s 2 -o static/

# see what would happen first
imgx "static/**/*.png" -f avif --dry-run

Why

Vectors stay sharp

SVG is rasterized at the exact target size with resvg, so -w and -s never resample.

Rasters are never enlarged

A width at or above the source width leaves the file alone. Upscaling only adds bytes.

Reads what you have

SVG, PNG, JPEG, WebP, AVIF, TIFF, GIF, BMP, ICO, TGA, PNM, plus HEIC, PSD, PDF and camera raw through macOS sips.

Safe to script

No prompts, no pager, no TTY. One line per file on stdout, failures on stderr, exit 1 when anything broke.

Idempotent

Existing outputs are skipped, so a retry after a partial failure only redoes the work that did not finish.

Dry runs

--dry-run resolves inputs, destinations and formats without touching the filesystem.

Formats

One row per format. imgx reads far more than it writes: everything in the Read column is an input, and only the formats marked in Write can be an output.

Format Extension Read Write Notes
svg .svg yes no Rasterized with resvg, so -w and -s produce genuinely sharp vectors at any size.
png .png yes yes Lossless, keeps transparency. The default output.
jpeg .jpg yes yes Lossy. Transparency is flattened onto --background.
webp .webp yes yes Lossy, keeps transparency, much smaller than PNG.
avif .avif yes yes Lossy, keeps transparency, smallest of the lot, slowest to encode.
tiff .tiff yes yes Lossless, uncompressed-ish, for print and archival.
gif .gif yes no First frame only.
bmp .bmp yes no Decoded natively.
ico .ico yes no Decoded natively.
tga .tga yes no Decoded natively.
pnm .pnm yes no Decoded natively.
heic .heic macOS no Decoded through sips, then converted as usual.
heif .heif macOS no Decoded through sips, then converted as usual.
psd .psd macOS no Decoded through sips, then converted as usual.
pdf .pdf macOS no Decoded through sips, then converted as usual.
camera raw .dng .cr2 .nef … macOS no Decoded through sips, then converted as usual.

There is no SVG output. Vectorizing a raster image is a different problem, and the result is never the original vector.

Homebrew tap

imgx is published as a Homebrew tap at github.com/chkrishnatej/homebrew-imgx. Tapping it gives you the binary, the imgx(1) manual page and the zsh completion function.

Install

brew tap chkrishnatej/imgx
brew install imgx
imgx --version

What you get

PathWhat
$(brew --prefix)/bin/imgxThe converter.
$(brew --prefix)/share/man/man1/imgx.1The manual page, so man imgx works.
$(brew --prefix)/share/zsh/site-functions/_imgxzsh completion, on $fpath already.

Update and remove

brew update
brew upgrade imgx

brew uninstall imgx
brew untap chkrishnatej/imgx

Work on the formula

The tap is an ordinary git repository. Clone it, point Homebrew at your copy, and rebuild: 

git clone https://github.com/chkrishnatej/homebrew-imgx
brew tap chkrishnatej/imgx \
  "$PWD/homebrew-imgx" --force

brew install imgx --build-from-source

The formula installs a prebuilt binary. Each release of chkrishnatej/imgx publishes one archive per platform, and the formula downloads the right one. A normal brew install imgx therefore needs no compiler, no Bun and no network access beyond the download.

Linux works the same way. The heic, psd, pdf and camera raw inputs need macOS sips, so they are macOS only.

Worth knowing before you point it at a folder of photographs. Rasters are never enlarged, animated GIF and WebP use their first frame, ICC profiles and EXIF are dropped, and the EXIF rotation flag is not applied. The manual lists every limitation.
