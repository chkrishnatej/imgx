NAME

imgx - convert images between common formats from the command line

SYNOPSIS

imgx input ... [options]

DESCRIPTION

imgx converts image files between formats. It reads SVG, PNG, JPEG, WebP, AVIF, TIFF, GIF, BMP, ICO and a few others, and writes PNG, JPEG, WebP, AVIF or TIFF.

Inputs may be files, directories, or glob patterns. A directory is walked recursively and every file with a recognised image extension is converted.

The output format comes from -f, or is inferred from the extension of -o. It defaults to PNG. Without -o, output is written next to each source file.

OPTIONS

-o, --out path
Where to write. A path ending in an image extension names a single output file. Anything else is treated as a directory, created if it does not exist, and the input folder structure is mirrored inside it. -o must be a directory when converting more than one file. If both -f and an -o file extension are given and they disagree, it is an error rather than a silently renamed file.
-f, --format fmt
One of png, jpeg, webp, avif, tiff. Default png.
-w, --width px
Target width. SVGs are rasterized at exactly this width, so the result is crisp at any size. Raster images are only ever shrunk; a width at or above the source width is ignored.
--height px
Target height, preserving aspect ratio. Ignored when --width is also given.
-s, --scale n
SVG only. Render at n times the intrinsic size. -s 2 gives a retina export.
-q, --quality 1-100
Encoder quality for jpeg, webp and avif. Ignored for png and tiff, which are lossless. Default 85. Quality 100 is the best a lossy codec offers, not a lossless mode.
--background css
The colour used to fill transparent pixels when writing JPEG, which has no alpha channel. Accepts #rrggbb, #rgb, rgb(r,g,b) or one of white, black, gray, grey, red, green, blue. Default white. An unrecognised colour is an error rather than a silent fallback.
--overwrite
Replace destination files that already exist. Without this flag an existing file is skipped.
--dry-run
Resolve inputs, outputs and formats, print what would be written, and exit without touching the filesystem.
-h, --help
Print usage to standard output and exit 0.
--version
Print the version and exit 0.

FORMATS

One row per format. The Read column lists the formats that can be used as an input. The Write column lists the formats that can be used as an output.

jpeg .jpg yes yes
webp .webp yes yes
avif .avif yes yes
tiff .tiff yes yes
gif .gif yes no
bmp .bmp yes no

svg is rasterized with resvg, so -w and -s produce genuinely sharp vectors at any size.

The heic , heif , psd , pdf and camera raw formats are handled through sips(1) on macOS and are unavailable elsewhere.

SVG is not an output format. Vectorising a photograph does not recover the curves it was drawn from.

EXIT STATUS

0
Every file converted, or was skipped because it already existed.
1
At least one file failed, or the arguments were invalid, or no input was given.

EXAMPLES

Convert a diagram for a web page, at exactly 2400 pixels wide:

imgx diagram.svg -w 2400

Produce a format macOS cannot write on its own:

imgx screenshot.png -f webp -q 90 -o images/

Convert a folder tree into a build directory that does not exist yet:

imgx screenshots/ -f webp -q 90 -o build/webp

Write one file to an exact name:

imgx logo.svg -o static/logo-2x.png

Check what a conversion would do before doing it:

imgx "static/**/*.png" -f avif --dry-run

AUTOMATION

imgx never prompts, never opens a pager, and never requires a terminal, so it can be driven from a script or an agent without a pseudo-terminal.

Progress goes to standard output, one line per file, in a fixed shape:

status  source -> destination  WxH  size

status is one of ok, skip, plan or fail. It is left-padded to four characters, so the columns line up; split on whitespace rather than on fixed offsets. ok lines end with dimensions and a byte size; skip and plan lines do not. fail lines go to standard error and carry the reason. The last line is a summary such as "3 converted, 1 skipped". With --dry-run the summary instead reads "N file(s) would be written".

Runs are idempotent. An existing destination is skipped rather than overwritten, so re-running a command after a partial failure only redoes the work that did not finish. Use --dry-run to resolve inputs and destinations without writing anything.

Because skip lines are not failures, an agent that wants a hard assertion should check the exit status and the failure count in the summary rather than assuming an empty output means nothing happened.

LIMITATIONS

No upscaling
Raster images are never enlarged by --width. Passing a width larger than the source leaves the file unchanged, by design.
Animation
Animated GIF and WebP use the first frame only.
Colour profiles
ICC profiles are not carried into the output. Pixels are not converted, so an image tagged Display P3 or AdobeRGB is written with the same numbers but without its tag, and viewers will read them as sRGB. Convert to sRGB before using imgx if colour accuracy matters.
EXIF orientation
The rotation flag in EXIF is not applied. Photographs whose pixels are stored sideways will be written sideways.
Metadata
EXIF, XMP and GPS data are not preserved.
Decoder safety
imgx has no sandbox. Malformed or hostile images are decoded by the same native libraries a browser uses, running as your user, so treat an image from an untrusted source with the caution you would apply to opening it in a browser.

FILES

completions/_imgx
zsh completion function, shipped in the imgx source tree. Copy or symlink it into any directory on $fpath. oh-my-zsh users can use ~/.oh-my-zsh/custom/completions, which is already on $fpath. Then open a new shell, since completion functions are indexed at startup.
